# 专家参数与 HTTP/3

大多数用户不需要改这里的任何值。专家模式适合明确知道瓶颈在哪里、并且愿意用可复现基准验证改动的人。

---

## 专家模式

入口：**设置 → 下载与调度 → 专家模式**。

关闭时，客户端使用固定策略；开启后，以下参数从 `settings.json` 的 `scheduler.expert` 读取，并覆盖自动策略。

### 调度与并发

| 参数 | 默认值 | 说明 |
| :--- | :--- | :--- |
| 调度 tick | `2000 ms` | 调度循环周期；调小会增加 CPU 占用 |
| 每主机最大连接 | `16` | 对单站点的并发上限；过高容易触发 429/503 |
| 全局最大工作线程 | `16` | 所有任务共享的 HTTP 分块线程上限 |
| 单任务最大线程 | `8` | 单个任务可获得的线程上限 |
| 单任务最小线程 | `0` | 0 表示不设下限，预算紧张时可排队 |
| AIMD 模式 | 保守 / 平衡（默认）/ 激进 | 控制提速与退避的激进程度 |
| 分块策略 | 自适应（默认）/ 固定 | 固定模式使用自定义分块大小 |
| 队列排序 | 优先级优先（默认）/ 最短任务优先 / FIFO | 自动调度模式下的排序键 |

### AIMD 细节

| 参数 | 默认值 |
| :--- | :--- |
| 降速阈值 / 提速阈值 / 严重下降阈值 | `0.16` / `0.04` / `0.50` |
| 冷却时间 | `3 s` |
| 采样数 / 探测稳定周期 | `1` / `2` |
| 降速系数 / 提速比例 | `0.50` / `0.25` |
| 振荡阈值 / 迟滞倍数 | `3` / `4` |

AIMD 的目标是找到链路可承受的并发，而不是把线程数拉满。固定高并发在弱网、共享出口或反滥用服务端上通常更快触发限流。

### 分块、长尾与重试

| 参数 | 默认值 | 说明 |
| :--- | :--- | :--- |
| 自定义分块大小 | `0`（自动） | 单位 MiB；过小增加请求开销，过大拉长长尾 |
| Tail Sprint 停滞窗口 / 最小拆分 | `8 s` / `1 MiB` | 对最后剩余的大分块做拆分重试 |
| Work-steal 最小拆分 | `2 MiB` | 空闲线程窃取尾部工作的最小粒度 |
| 连接 / 读取超时 | `30 s` / `30 s` | 范围分别为 3–120 s、5–300 s |
| 连接池空闲上限 / TCP Keepalive | `20` / `60 s` | 每个主机的空闲连接与保活 |
| 重试退避基数 / 上限 / 抖动 | `250 ms` / `4000 ms` / `25%` | 指数退避参数 |

### 什么时候该改

- **服务端 429/503 频繁**：先降低每主机最大连接与单任务最大线程，再考虑保守 AIMD。
- **长尾明显**：确认 Tail Sprint 开启，适当降低最小拆分或提高停滞窗口。
- **小文件很多**：固定小分块可能增加开销；保持自动通常更好。
- **高延迟链路**：不要盲目调大超时；先确认是丢包、代理还是镜像问题。
- **CPU 占用偏高**：检查调度 tick、并发线程与 BT 上传；不要用调小 tick 来“加速”。

:::caution[变更后请验证]
任何专家参数改动都应配合[性能基准](/advanced/benchmarks/)或同 URL 的 `curl` 对照，至少重复 3 次。单次“感觉快了”不足以说明问题。
:::

## HTTP/3 与 Alt-Svc

HTTP/3 默认启用，但**不在设置对话框中**，开关位于 `settings.json`：

```json
{
  "scheduler": {
    "http3AltSvcEnabled": true
  }
}
```

### 启用条件

客户端只有在以下条件全部满足时才会尝试 HTTP/3：

1. 开关为开启；
2. **代理模式为直连**（QUIC 不能泄漏到代理路径）；
3. 目标是 HTTPS；
4. 存在该源站的有效、未过期的 `Alt-Svc` 记录；
5. 该源站不在 HTTP/3 失败熔断的退避窗口内。

`Alt-Svc` 记录来自响应头，只保留 `h3` 系列（优先标准 `h3`），并缓存在 SQLite 中，跨任务、跨会话保留。

### 尝试与回退

- 每个请求只尝试 **一次** HTTP/3，超时 **5 秒**；
- 失败或超时后回退到正常的 TCP 重试路径；
- 失败会触发按源站的熔断：约 `5 分钟 → 10 分钟 → 30 分钟 → 24 小时` 指数退避；
- 一旦 HTTP/3 成功，熔断状态清除。

### 什么时候关闭

- 本机或防火墙阻断 UDP 443；
- 代理/VPN 环境要求所有流量走 TCP；
- 某些网络对 QUIC 有 QoS 限制，导致首包超时；
- 你正在排查连接问题，需要先排除 HTTP/3 变量。

关闭后仍使用 HTTP/1.1 或 HTTP/2（取决于服务端与连接协商），下载功能不受影响。
