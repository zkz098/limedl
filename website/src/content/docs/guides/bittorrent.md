# BitTorrent 协议与调优

limedl 深度集成了现代化纯 Rust 原生 BitTorrent 引擎（**Irontide**），具备完备的现代 P2P 协议族规范支持，兼顾高吞吐下载、低内存开销与强穿透能力。

---

## 协议特性支持一览

limedl 严格遵循 BitTorrent 官方强化规范（BEP - BitTorrent Enhancement Proposals），支持以下核心特性：

| 协议标准 | 规范名称 | 详细说明与技术优势 |
| :--- | :--- | :--- |
| **BEP 03** | 核心传输协议 | 基础的 Peer-to-Peer 分块传输、Choke/Unchoke 握手状态机与位图（Bitfield）管理。 |
| **BEP 05** | 分布式哈希表 (DHT) | 采用标准 Kademlia 算法的 **Mainline DHT** 网络。即使所有中心 Tracker 服务器全部离线，仍能通过全网去中心化节点在数秒内寻址到 Peer。 |
| **BEP 09** | 磁力元数据交换 (ut_metadata) | 支持磁力链接（`magnet:?xt=urn:btih:...`）在下载数据前，直接向初始 Peer 请求种子的元数据字典，实现无需 `.torrent` 文件即可秒级展示文件树。 |
| **BEP 10** | 扩展协议握手 (Extension Protocol) | 允许 Peer 之间动态协商支持的高级功能（如元数据交换、PEX 对等交换等）。 |
| **BEP 11** | 对等节点交换 (PEX) | 在 Swarm 群集中的 Peer 之间直接交换彼此知晓的活跃 Peer IP 列表，极大加速找人速度。 |
| **BEP 14** | 本地服务发现 (LSD) | 自动向局域网广播组播探测。同一路由器或交换机下的局域网设备互传将绕过广域网，直接跑满千兆/万兆局域网内网带宽。 |
| **BEP 15** | UDP Tracker 协议 | 采用高效、低开销的 UDP 报文与 Tracker 通信，显著减少网络拥塞。 |
| **UPnP / NAT-PMP** | 自动端口映射 | 自动向家用路由器申请开通外网监听端口，将内网设备转变为拥有公网入站能力的活跃节点。 |
| **MSE / PE** | 传输层加密 | 优先启用流加密，防止网络运营商（ISP）的深度包检测（DPI）技术识别并限制 BT 流量。 |

## 磁力链接极速解析流程

在 limedl 中粘贴磁力链接后，后台引擎会经历以下流畅阶段：

```
┌────────────────┐      提取 InfoHash       ┌────────────────┐
│ 1. 磁力链接解析│ ───────────────────────► │ 40位十六进制哈希│
└───────┬────────┘                          └───────┬────────┘
        │                                           │
        ▼                                           ▼
┌────────────────┐      Kademlia 寻址       ┌────────────────┐
│ 2. DHT 节点查询│ ───────────────────────► │ 获取候选 Peer  │
└───────┬────────┘                          └───────┬────────┘
        │                                           │
        ▼                                           ▼
┌────────────────┐      ut_metadata 握手    ┌────────────────┐
│ 3. 元数据拉取  │ ───────────────────────► │ 解析出种子结构 │
└───────┬────────┘                          └───────┬────────┘
        │                                           │
        ▼                                           ▼
┌────────────────┐      弹窗勾选所需子文件   ┌────────────────┐
│ 4. 文件列表展示│ ───────────────────────► │ 确认开始分块下载│
└────────────────┘                          └────────────────┘
```

1. **瞬时解析**：从 URI 中提取 InfoHash 及可选的 Tracker 参数（`tr`）；
2. **DHT 闪电寻址**：向本地 DHT 路由表中的已知优质节点广播 `get_peers` 请求；
3. **获取元数据**：与率先连接的 Peer 协商 `ut_metadata` 消息，逐块下载 torrent 元数据；
4. **子文件精准选择**：元数据解析完成后，弹窗呈现完整的目录层级。你可以自由勾选需要下载的子文件（例如电视剧只选前两集），取消勾选的文件将不占用任何磁盘空间。

## 核心调优与网络穿透实战

要让 BitTorrent 下载速度达到宽带上限，网络连通性至关重要。

### 1. 确保路由器开启 UPnP
- 进入家庭路由器的管理后台（通常为 `192.168.1.1` 或 `192.168.0.1`）；
- 在“高级设置”或“路由功能”中找到 **UPnP**，将其设置为 **启用 (Enabled)**；
- limedl 启动后会自动在路由器上映射 TCP/UDP 端口（默认为 `6881`）。当其他外网 Peer 能够主动连接你的客户端时，你的连通性（Connectability）将显著提升。

### 2. 维护高质量公共 Tracker 列表
虽然 DHT 已经能完全独立工作，但添加优质公共 Tracker 列表能够为冷门种子提供双重保障。

在 **设置 -> BT 设置 -> 公共 Tracker** 输入框中，推荐粘贴网络上定期更新的活跃 Tracker 列表（每行一个）。limedl 会在每次新建下载时自动将这批 Tracker 注入到任务中。

### 3. 上传限速与分享率控制
在家庭宽带（尤其是 ADSL 或非对称光纤）中，如果将上行上传带宽完全跑满，会导致 TCP ACK 确认包严重延迟，进而反噬下载速度，甚至导致网页浏览卡顿。

- **上传限速**：推荐在 **设置 -> 速度限制** 中，将全局上传限制设为宽带实际最大上行速率的 **70% ~ 80%**。
- **做种分享率 (Seeding Ratio)**：默认为 `1.0`。即当上传流量达到下载流量的 1 倍时自动结束任务，既回馈了 P2P 社区，又不会长期无度占用系统资源。

## 反吸血与安全性机制

limedl 内置了针对 P2P 网络中恶意 Peer 的防御感知逻辑：
- **恶意客户端侦查**：识别修改客户端标识、只下载不上传或发送伪造垃圾分块（Corrupt Blocks）的恶意节点；
- **智能降级与熔断**：一旦某个 Peer 连续返回校验错误的坏块，引擎会自动切断连接并将其暂时列入黑名单，保障下载数据的绝对纯净与带宽不被白白浪费。
