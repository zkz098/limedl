# 配置手册

limedl 的配置统一保存在应用数据目录下的 `settings.json` 中，并通过内存事务与磁盘原子重命名（`.json.tmp` → `.json`）保证并发读写安全。

在客户端主界面点击左侧 **设置** 图标即可打开图形化设置面板；部分引擎级参数（例如 HTTP/3）只存在于 `settings.json`，本文会单独标注。

---

## 1. 常规与外观 (General & Appearance)

| 配置项 | 可选值 / 默认值 | 说明 |
| :--- | :--- | :--- |
| **界面语言** | 简体中文 / 繁體中文 / English / 跟随系统（默认） | 即时切换界面语言。 |
| **主题色彩** | 浅色 / 深色 / 跟随系统（默认） | 跟随系统时随操作系统的明暗模式自动切换。 |
| **主色调** | 琥珀 (Amber) / 天蓝 (Sky) / 青柠 (Lime，默认) / 紫罗兰 (Violet) / 黑白 (Monochrome) | 选择强调色与主题风格。 |
| **背景不透明度** | 默认 / 亚克力 (Acrylic) / 磨砂 (Frosted) | 控制主窗口背景的透明与模糊程度，默认不启用。 |
| **关闭主窗口行为** | 最小化到托盘（默认）/ 退出应用 | 选择关闭按钮是静默驻留托盘继续下载，还是直接退出。 |
| **开机自启动** | 开启 / 关闭（默认） | 注册系统启动项；自启时携带 `--hidden`，静默驻留托盘。 |
| **下载时抑制休眠** | 开启（默认）/ 关闭 | 仅在存在活动任务时申请电源锁，最后一个任务结束后释放；屏幕仍可关闭。 |
| **系统通知** | 开启 / 关闭（默认） | 任务完成或失败时发送桌面通知。 |
| **双击已完成任务** | 无操作（默认）/ 打开文件 / 在文件管理器中定位 / 打开下载目录 | 任务列表中的双击动作。 |
| **双击未完成任务** | 无操作（默认）/ 暂停或继续 | 对未完成任务的双击动作。 |
| **紧凑视图** | 开启 / 关闭（默认） | 关闭时为卡片视图，开启后为紧凑表格视图。 |
| **显示详情信息** | 开启（默认）/ 关闭 | 是否在任务卡片中展示速度、ETA 等次要信息。 |
| **可见列** | 文件名、大小、已下载、状态、进度、速度、ETA（默认） | 表格视图显示的列；文件名列始终保留。 |
| **内存中保留任务数** | 默认 `200` | `maxInMemoryDownloads`：内存中保留的已完成/失败任务上限，超出后按时间淘汰；数据库记录不受影响。 |

## 2. 网络与代理 (Network & Proxy)

| 配置项 | 可选值 / 默认值 | 说明 |
| :--- | :--- | :--- |
| **代理模式** | 直连（默认）/ 系统代理 / 手动代理 | **直连**：不使用代理。**系统代理**：读取操作系统静态代理配置（Windows Internet 选项 / macOS 网络设置），不支持 PAC/WPAD。**手动代理**：使用下方 URL。 |
| **手动代理地址** | 空 | 直接填写完整 URL，例如 `http://127.0.0.1:7890` 或 `socks5://127.0.0.1:1080`；协议由 URL scheme 决定，没有独立的协议下拉框。 |
| **默认 User-Agent** | 内置现代 Chrome UA | HTTP 下载使用的 UA；遇到反爬镜像站时可自定义。 |
| **自动识别校验和** | 开启（默认）/ 关闭 | 优先使用响应头中的校验和（RFC 3230/9530、S3、GCS），其次探测 `.sha256`、`SHA256SUMS` 等伴随文件。 |
| **默认重试次数** | 默认 `5` | 单个任务在遇到可重试错误时的最大重试次数。 |
| **连接 / 读取超时** | 默认 30s / 30s | 非专家模式下固定 30 秒；开启专家模式后可分别调整（连接 3–120s，读取 5–300s）。 |

## 3. 下载与调度 (Downloads & Scheduler)

| 配置项 | 可选值 / 默认值 | 说明 |
| :--- | :--- | :--- |
| **默认下载目录** | 本地路径 | 新建任务时的默认保存目录；应为绝对路径。 |
| **调度模式** | 智能自适应（默认）/ 传统队列 | 智能自适应按线程预算分配并发；传统模式按优先级与创建时间激活任务。 |
| **传统模式并行任务数** | 1–32，默认 `3` | 仅传统模式下生效，最多同时处于“下载中”的任务数。 |
| **全局最大工作线程** | 1–64，默认 `16` | 所有任务共享的 HTTP 分块工作线程上限。 |
| **单任务最大线程** | 1–32，默认 `8` | 智能自适应模式下单个任务可获得的线程上限。 |
| **单任务最小线程** | 默认 `0` | 0 表示不设下限；线程预算紧张时任务可被降到 0 并排队。 |
| **AIMD 自适应模式** | 保守 / 平衡（默认）/ 激进 | 控制加法提速与乘法退避的激进程度。 |
| **分块策略** | 自适应（默认）/ 固定 | 固定策略使用专家模式中的自定义分块大小（0 表示按任务大小自动选择）。 |
| **Tail Sprint** | 开启 / 关闭（默认） | 尾部冲刺：对最后剩余的大分块做拆分与重试，减少长尾。 |
| **连接预热** | 开启（默认）/ 关闭 | 下载开始前预先建立部分连接，降低首字节等待。 |
| **自动校验和模式** | None / Blake3（默认）/ SHA-256 / SHA-512 | 下载完成后校验的算法；`None` 表示不校验。注意：通用校验失败时任务会标记为失败并保留 `.part.corrupt`，不会自动重下“坏块”；Metalink 的 piece 校验是独立的逐片机制。 |
| **HTTP/3 Alt-Svc** | `settings.json` 中 `scheduler.http3AltSvcEnabled`，默认开启 | 允许对支持 Alt-Svc 的主机尝试 HTTP/3（QUIC）；失败会熔断并回退 TCP，需要本机 UDP 443 可用。此项不在设置对话框中。 |

### 专家模式 (Expert Mode)

开启 **设置 → 下载与调度 → 专家模式** 后，可以覆盖上述自动策略。常用参数：

| 参数 | 默认值 | 说明 |
| :--- | :--- | :--- |
| 调度 tick | `2000 ms` | 调度循环周期。 |
| 每主机最大连接 | `16` | 防止对单站点过度并发。 |
| AIMD 降速阈值 / 提速阈值 / 严重下降阈值 | `0.16` / `0.04` / `0.50` | 吞吐变化达到阈值时触发对应动作。 |
| AIMD 冷却时间 | `3 s` | 降速后的观察期。 |
| AIMD 采样数 / 探测稳定周期 | `1` / `2` | 连续满足条件的周期数。 |
| AIMD 降速系数 / 提速比例 | `0.50` / `0.25` | 乘法退避与加法步长。 |
| 振荡阈值 / 迟滞倍数 | `3` / `4` | 抑制线程数反复震荡。 |
| 自定义分块大小 | `0`（自动） | 单位 MiB，0 表示按文件大小自动选择。 |
| Tail Sprint 停滞窗口 / 最小拆分 | `8 s` / `1 MiB` | 尾部冲刺的触发条件。 |
| Work-steal 最小拆分 | `2 MiB` | 空闲线程窃取尾部工作的最小粒度。 |
| 连接 / 读取超时 | `30 s` / `30 s` | 范围分别为 3–120s、5–300s。 |
| 连接池空闲上限 / TCP Keepalive | `20` / `60 s` | 每个主机的空闲连接与保活。 |
| 重试退避基数 / 上限 / 抖动 | `250 ms` / `4000 ms` / `25%` | 指数退避参数。 |
| 队列排序策略 | 优先级优先（默认）/ 最短任务优先 / FIFO | 自动调度模式下的排序键。 |

## 4. 速率限制与时间表 (Speed Limits & Schedule)

- **全局下载限速**：单位 KB/s 或 MB/s，`0` 表示不限速；基于令牌桶平滑限速。
- **全局上传限速**：限制 BitTorrent 上行，避免占满上行导致 ACK 延迟升高。
- **定时限速计划 (Speed Schedule)**：
  - 规则只按**本地时间的小时段**匹配，不区分星期或日期；
  - `start_hour` 含、`end_hour` 不含（例如 9–18 表示 09:00 到 17:59）；
  - `start_hour > end_hour` 表示跨越午夜（例如 22–6）；
  - 多条规则按顺序匹配，第一条生效；未命中时回退全局限速；
  - 限速值 `0` 表示该时段不限速。

示例：

- 每天 `09:00 - 18:00`：限制下载为 `2000 KB/s`；
- 每天 `00:00 - 08:00`：不限速（`0`）。

## 5. BitTorrent P2P 设置 (BitTorrent Settings)

limedl 的 BT 后端基于 **librqbit**，支持 DHT、UPnP、PEX 与 LSD 等现代协议。PEX/LSD/传输加密不是可开关的用户选项，由引擎按协议行为处理。

| 配置项 | 可选值 / 默认值 | 说明 |
| :--- | :--- | :--- |
| **监听端口** | 默认留空（系统分配）；可指定 `6881` 等 | P2P 传入连接的 TCP/UDP 端口。 |
| **UPnP 端口映射** | 开启 / 关闭（默认） | 在支持 UPnP 的路由器上自动申请端口映射。 |
| **分布式哈希表 (DHT)** | 开启（默认）/ 关闭 | Mainline DHT，磁力链接无需 Tracker 即可找 Peer。 |
| **IPv6** | 开启（默认）/ 关闭 | 监听与连接 IPv6。 |
| **µTP** | 开启（默认）/ 关闭 | BEP 29 微传输协议，改善拥塞与 NAT 场景。 |
| **最大同时下载数** | 默认 `5` | 同时活跃的 BT 任务上限。 |
| **单任务最大 Peer 数** | 默认 `128` | 单个种子的连接上限。 |
| **全局下载 / 上传限速** | 默认 `0`（不限） | BT 专用的上下行限速。 |
| **上传限速 / 分享率** | 上传限速默认 `0`；分享率默认 `0`（不限） | 达到分享率后停止做种；勾选“达到上传限制时暂停上传”可提前暂停。 |
| **轻量 BT 模式** | 开启 / 关闭（默认） | 空闲或无活跃种子时卸载 BT 引擎，按需拉起，降低常驻内存。 |
| **公共 Tracker 列表** | 默认内置列表 URL | 新建磁力/种子任务时自动注入的 Tracker 列表来源。 |
| **反吸血** | 开启 / 关闭（默认） | 默认宽限 300s、回馈比率 0.1、封禁 3600s、限流时最多 4 个上传槽位；可选仅限流或直接封禁。 |
| **IP 黑名单** | 开启 / 关闭（默认） | 从 eMule `.dat` 或纯文本 CIDR 文件加载黑名单。 |

## 6. Aria2 RPC 接口设置 (Aria2 RPC)

limedl 内置兼容 Aria2 的 JSON-RPC 2.0 服务端，同时提供 HTTP POST 与 WebSocket（路径均为 `/jsonrpc`）。出于安全考虑，**默认关闭**。

- **启用 Aria2 RPC**：默认关闭，需在设置中勾选。
- **监听地址 / 端口**：默认 `127.0.0.1:6800`；非回环监听时守护进程要求配置密钥。
- **鉴权模式**：
  - **共享密钥 (Single)**：全局 Token，请求参数使用 `token:<密钥>`；
  - **多客户端独立 Token (PerClient)**：为每个客户端分配独立 Token，本地仅保存 Argon2id 哈希与不可逆的明文前缀，便于识别。
- **CORS**：默认允许 `http://localhost` 与 `http://127.0.0.1`；可添加额外 Origin，或允许所有 Origin（`*`，仍要求 Token）。
- **退出行为**：桌面端默认忽略 `aria2.shutdown`；`limedl-server` 守护进程会将其映射为进程退出。

## 7. 存储与缓冲池 (Storage & Buffer Pool)

### 介质探测与覆盖

- Windows 通过存储设备属性识别 SSD/HDD；网络共享、映射盘与 Linux/macOS 网络挂载视为“网络位置”，按 SSD 方式调度。
- `\\wsl$\<发行版>` 会解析背后的 `ext4.vhdx`，按宿主卷的真实介质调度。
- **目录介质覆盖 (`disk_type_overrides`)**：在 **设置 → IO 实验室 → 目录介质覆盖** 中按目录指定 SSD/HDD；规范化路径前缀匹配，最长匹配胜出，保存后立即重建 I/O 队列。

### 缓冲池参数

| 配置项 | 默认值 | 说明 |
| :--- | :--- | :--- |
| HDD 缓冲池上限 | `1024 MiB` | 所有 HDD 下载共享的写缓冲内存上限。 |
| HDD 并行缓冲槽 | `4` | 同时进行的 HDD 顺序写缓冲数量。 |
| HDD 双缓冲 | 开启 | 关闭后 HDD 改用较小的写合并缓冲。 |
| SSD 写合并缓冲 | `0`（自动，按分块大小） | 单任务 SSD 写合并上限，最大 4096 MiB。 |
| Game Mode 缓冲 | `128 MiB` | 游戏/性能模式下的缓冲大小。 |
| Game Mode 并行槽 | `1` | 游戏模式下降到的并行缓冲数量。 |

Game Mode 与 Overclock Mode 是运行时开关，不写入 `settings.json`：前者降低磁盘 I/O 干扰，后者放宽并发限制。

## 9. 实验室 (Labs)

- **CDN 探针加速**：支持 **Cloudflare**（默认）、**Fastly** 与 **自定义 Provider**。
  - 自定义 Provider 可填写测速 URL 与 IPv4/IPv6 CIDR 列表；
  - 测速会消耗 20–50 MB 流量，完成后可应用最优边缘 IP；
  - 加速仅对匹配所选 Provider 网段的域名生效，失败会回退普通 DNS。
- **URL 重写规则 (URL Rewrite Rules)**：按 Host / 前缀 / 正则 / 通配符匹配，将慢速源改写为镜像，可设置请求头与替换模板。
- **完整性校验**：任务右键菜单提供“校验文件完整性”，见 [任务管理](/guides/tasks/)。
