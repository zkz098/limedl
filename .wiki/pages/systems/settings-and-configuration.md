# Settings and Configuration

Configuration is a JSON file, not SQLite. `SettingsService` owns it as the single
source of truth for every backend and frontend, and `Dispatcher::save_settings_with`
is the only supported write path.

## AppSettings

`AppSettings` is a flat struct of `#[serde(default)]` sub-settings:
`appearance`, `power`, `proxy`, `scheduler`, `download`, `bt`, `logging`,
`aria2_rpc`, `cdn_acceleration`, `url_rewrite`, `global_speed_limit_bps`,
`speed_limit_schedule`, `notifications`, `io_baseline`, `autostart`,
`setup_completed`, `last_setup_step`, `double_click` and
`max_in_memory_downloads` [[cite:crates/limedl-types/src/types/settings.rs:L714-L759]].
Because every field has a serde default, a partial or hand-edited file still
loads and unknown keys are ignored — a point the loader itself documents, since
unknown *enum values* are not ignored (serde rejects the whole document)
[[cite:crates/limedl-types/src/settings/mod.rs:L479-L483]].

Structs use `#[serde(rename_all = "camelCase")]`
[[cite:crates/limedl-types/src/types/settings.rs:L714-L716]] and enums use
`snake_case` [[cite:crates/limedl-types/src/types/settings.rs:L52-L59]], so the
on-disk JSON is camelCase.

The type definitions live in the `limedl-types` crate (foundation layer), and
`limedl-core` re-exports them, so every historical `limedl_core::types::…` path
still resolves.

## Where settings.json lives

The desktop resolves the base data directory in `paths::dirs_or_temp_dir`
[[cite:crates/limedl-native/src/paths.rs:L3-L14]]:

| Platform | Base directory |
| --- | --- |
| Windows | `%LOCALAPPDATA%\limedl` |
| macOS | `~/Library/Application Support/limedl` |
| Linux | `$XDG_DATA_HOME/limedl` or `~/.local/share/limedl` |
| Override | `LIMEDL_DATA_DIR` wins over all of the above |

The platform rows come from `dirs_local_data_dir`
[[cite:crates/limedl-native/src/paths.rs:L16-L31]]; `LIMEDL_DATA_DIR` is checked
first [[cite:crates/limedl-native/src/paths.rs:L6-L8]], and when no platform
directory resolves the base falls back to a temp directory
[[cite:crates/limedl-native/src/paths.rs:L9-L13]].

`settings.json` sits in that base directory and the SQLite DB/torrent state live
in `<base>/downloads`. `SystemContext::with_components` derives the settings path
as the **parent** of `state_dir` joined with `settings.json`
[[cite:crates/limedl-core/src/context.rs:L43-L55]], and opens the database as
`<state_dir>/downloads.db` [[cite:crates/limedl-core/src/context.rs:L58-L59]].
The headless `limedl-server` daemon resolves the same base directory (with
`--data-dir` as an additional highest-precedence override) through its own
`resolve_data_dir` [[cite:crates/limedl-server/src/config.rs:L88-L99]], a
precedence the daemon documents as deliberately matching the desktop so a daemon
can read a desktop profile's settings and vice versa
[[cite:crates/limedl-server/src/config.rs:L1-L8]]; its state directory is
`data_dir/downloads`, matching the settings-path rule one level up
[[cite:crates/limedl-server/src/config.rs:L41-L43]].

## SettingsService: serialized read-modify-write

`SettingsService` holds an `Arc<RwLock<AppSettings>>` plus a
`tokio::sync::Mutex` `update_lock`
[[cite:crates/limedl-disk/src/services/settings_service.rs:L11-L19]].
`update_with(mutate)` takes the lock, clones the current settings as the base,
applies the closure, then `persist()` [[cite:crates/limedl-disk/src/services/settings_service.rs:L47-L58]]:

1. `normalize_settings(candidate)`;
2. `persist_settings` to disk atomically;
3. replace the in-memory value and return it.

Step order is the `persist` helper
[[cite:crates/limedl-disk/src/services/settings_service.rs:L60-L66]]. The lock is
what makes concurrent saves safe — without it two saves could each clone the
same stale base and the later write would silently drop the other's change
[[cite:crates/limedl-disk/src/services/settings_service.rs:L15-L17]], a property
pinned by a ten-way concurrent-update test
[[cite:crates/limedl-disk/src/services/settings_service.rs:L100-L128]]. A closure
that returns an error aborts before persistence, leaving the stored settings
untouched [[cite:crates/limedl-disk/src/services/settings_service.rs:L130-L148]].
`update` is the whole-struct variant [[cite:crates/limedl-disk/src/services/settings_service.rs:L41-L45]],
`factory_reset` saves `AppSettings::default()`
[[cite:crates/limedl-disk/src/services/settings_service.rs:L68-L72]], and
`get`/`get_blocking` are the reads [[cite:crates/limedl-disk/src/services/settings_service.rs:L31-L39]].

### Atomic persistence

`persist_settings` creates the parent directory, writes `settings.json.tmp`,
**flushes and `sync_all`s it**, snapshots the outgoing file to
`settings.json.bak` (best effort — a failure only logs), and renames the temp
file over `settings.json`
[[cite:crates/limedl-types/src/settings/mod.rs:L571-L593]]. The snapshot itself
is `back_up_settings` [[cite:crates/limedl-types/src/settings/mod.rs:L595-L607]].
The fsync before the rename matters: without it a power loss can make the rename
durable while the data is not, leaving an empty `settings.json` behind — exactly
the unreadable-file case the recovery path below exists for
[[cite:crates/limedl-types/src/settings/mod.rs:L578-L580]].

### Unreadable settings do not block startup

`load_settings` is infallible for a *content* problem. A missing file returns the
defaults; an unreadable one (permissions, I/O) still returns `Err`, because that
is an environment problem rather than a corrupt file
[[cite:crates/limedl-types/src/settings/mod.rs:L470-L477]]. When the contents
cannot be parsed or normalized it does not propagate the error
[[cite:crates/limedl-types/src/settings/mod.rs:L489-L513]]:

1. the file is moved aside to `settings.json.corrupt` (so the next save can create
   a fresh one and the user can still inspect what was there)
   [[cite:crates/limedl-types/src/settings/mod.rs:L546-L560]];
2. `settings.json.bak` is tried, and its value is used if it parses and
   normalizes [[cite:crates/limedl-types/src/settings/mod.rs:L562-L569]];
3. otherwise `AppSettings::default()` applies
   [[cite:crates/limedl-types/src/settings/mod.rs:L507-L511]].

Either way the outcome is an `error!` log entry. Before this, one bad byte in
`settings.json` made every start fail with an error the GUI had nowhere to show
[[cite:crates/limedl-types/src/settings/mod.rs:L485-L488]]. Parsing first runs a
legacy migration: a `defaultChecksum` value outside the supported set
(`none`/`blake3`/`sha256`/`sha512`) is rewritten to `blake3` instead of
quarantining an otherwise-readable file
[[cite:crates/limedl-types/src/settings/mod.rs:L522-L544]].

## normalize_settings

All externally supplied settings pass through `normalize_settings`, which is the
key validation point [[cite:crates/limedl-types/src/settings/mod.rs:L116-L197]]:

- **Proxy**: `Disabled`/`System` clear `manual_url`; `Manual` requires a non-empty,
  parseable URL [[cite:crates/limedl-types/src/settings/mod.rs:L91-L114]].
- **Scheduler**: traditional `max_parallel_tasks` clamped to 1..=32, automatic
  `max_parallel_threads` to 1..=64, per-task threads to 1..=32 and never above the
  global max [[cite:crates/limedl-types/src/settings/mod.rs:L118-L133]];
  `min_threads_per_task` defaults to half the max when 0
  [[cite:crates/limedl-types/src/settings/mod.rs:L247-L253]]. The expert-mode
  block (AIMD thresholds, timeouts, backoff) is clamped field by field in
  `normalize_expert_settings` [[cite:crates/limedl-types/src/settings/mod.rs:L42-L89]].
- **Download**: retries clamped to 0..=20
  [[cite:crates/limedl-types/src/settings/mod.rs:L175-L181]], User-Agent normalized
  (empty → default Chrome UA, >512 bytes or invalid header characters → error)
  [[cite:crates/limedl-types/src/settings/mod.rs:L28-L40]], and
  `default_download_dir` dropped to empty unless absolute
  [[cite:crates/limedl-types/src/settings/mod.rs:L270-L280]].
- **IO baseline**: buffer limits, game-mode limits and HDD parallelism clamped to
  safe ranges [[cite:crates/limedl-types/src/settings/mod.rs:L141-L150]].
- **Logging**: level kept, path trimmed, retention count/days clamped
  [[cite:crates/limedl-types/src/settings/mod.rs:L260-L268]].
- **BT**: `normalize_bt_settings` validates the listen port and port range,
  clamps `max_downloads`, peers and upload/ratio limits
  [[cite:crates/limedl-types/src/settings/mod.rs:L282-L343]]; the tracker list is
  parsed per line with http/https/udp schemes only, then sorted and de-duplicated
  [[cite:crates/limedl-types/src/settings/mod.rs:L358-L401]], and the tracker-list
  URL must be http/https
  [[cite:crates/limedl-types/src/settings/mod.rs:L403-L419]].
- **Aria2 RPC**: `normalize_aria2_rpc_settings` drops clients whose `token_hash`
  is empty (they can never verify, so they would only be dead UI rows) and trims
  names/hashes [[cite:crates/limedl-types/src/settings/mod.rs:L199-L226]];
  `listen_address` falls back to `127.0.0.1` unless `is_plausible_bind_host`
  accepts it — an IP literal or bare hostname; a `host:port`, URL or whitespace is
  rejected so `format_bind_addr` cannot append a second port
  [[cite:crates/limedl-types/src/settings/mod.rs:L228-L245]]; blank CORS origins
  are trimmed and dropped [[cite:crates/limedl-types/src/settings/mod.rs:L219-L224]].
- **URL rewrite**: rules with an empty pattern are dropped, targets with an empty
  template are dropped, and `order` is reassigned to the filtered positions
  [[cite:crates/limedl-types/src/settings/mod.rs:L421-L468]].
- `max_in_memory_downloads` is 0 (unlimited) or clamped to 10..=10000
  [[cite:crates/limedl-types/src/settings/mod.rs:L255-L258]].

## Power settings (`power.preventSleep`)

`power` is the one sub-setting whose *default* carries the most weight.
`PowerSettings { prevent_sleep }` uses `#[serde(default = "default_true")]` and
an `impl Default` that returns `true`, so a fresh install, a partial file and a
`settings.json` written before the section existed all end up with sleep
inhibition **on** [[cite:crates/limedl-types/src/types/settings.rs:L687-L712]]. It
is the current example of the "missing key keeps the intended default, unknown
keys are ignored" contract above.

The promise the flag makes is deliberately narrow, because the desktop's
`PowerGuard` is the only thing acting on it: the lock is a keep-awake system
assertion taken only while tasks run and released when the last one finishes, the
display may still turn off, and a privileged suspend request, `shutdown` or the
laptop lid still wins [[cite:crates/limedl-native/src/power.rs:L1-L28]]. Turning
the setting off leaves the OS power policy untouched
[[cite:crates/limedl-types/src/types/settings.rs:L692-L697]].

`normalize_settings` carries the section through unchanged — a boolean needs no
clamping [[cite:crates/limedl-types/src/settings/mod.rs:L152-L155]] — and tests
pin both directions: a file without the key keeps the default
[[cite:crates/limedl-types/src/settings/tests.rs:L515-L543]], an explicit `false`
survives a save/load round trip
[[cite:crates/limedl-types/src/settings/tests.rs:L545-L557]], and normalization
preserves it [[cite:crates/limedl-types/src/settings/tests.rs:L559-L567]].

Only `limedl-native` acts on the value: `SettingsSync::push_ui` feeds
`power.prevent_sleep` into `POWER_GUARD.set_enabled` on the UI thread (on Windows
the power flag is thread-local)
[[cite:crates/limedl-native/src/settings_sync.rs:L143-L160]]. `limedl-server`
persists and reads the same `settings.json` verbatim but performs no host power
management — a container cannot decide its host's suspend policy, and the type
itself records that only desktop clients act on the flag
[[cite:crates/limedl-types/src/types/settings.rs:L699-L701]] — so a daemon
deployment keeps the host awake through host configuration. The desktop half —
one RAII backend per platform and the best-effort failure behavior — is in
[[wiki:desktop/native-ui-architecture]]; the daemon half in
[[wiki:integrations/headless-server-daemon]].

## Aria2 RPC authentication and bind settings

`Aria2RpcSettings` has `enabled` (**default `false`**), `port` (default 6800),
`listen_address` (default `127.0.0.1`), an optional `secret`, `auth_mode`,
`clients`, `cors_allowed_origins`, `allow_any_origin` (default `false`) and
`exit_on_shutdown` (default `false`)
[[cite:crates/limedl-types/src/types/settings.rs:L606-L644]]. `Aria2AuthMode` is
`single` (the default, preserving the historical shared secret) or `per_client`
[[cite:crates/limedl-types/src/types/settings.rs:L576-L587]].

The `enabled` default flipped from `true` to `false`: with an empty `secret` the
endpoint answers anonymously, so a fresh install must not expose it until the
user opts in; an existing `settings.json` that already says `"enabled": true` is
honoured [[cite:crates/limedl-types/src/types/settings.rs:L646-L666]]. If no
secret is configured while the server is on, `serve` logs a warning that any
local process can control downloads
[[cite:crates/limedl-rpc/src/server.rs:L185-L195]].

`listen_address` is what lets the headless daemon serve a LAN. It is not a pure
preference: a non-loopback value only starts together with authentication,
enforced by `public_bind_rejection`, which the server calls before binding
[[cite:crates/limedl-rpc/src/server.rs:L56-L73]]
[[cite:crates/limedl-rpc/src/server.rs:L177-L183]]. `allow_any_origin` emits a
CORS wildcard (with credentials deliberately off, since browsers reject the
combination) [[cite:crates/limedl-rpc/src/server.rs:L75-L91]] and
`exit_on_shutdown` lets `aria2.shutdown` stop the process
[[cite:crates/limedl-types/src/types/settings.rs:L639-L643]]; both default to the
desktop's safe behavior and the daemon turns them on
[[cite:crates/limedl-server/src/lib.rs:L85-L102]].

`Aria2Client` carries `id`, `name`, `token_hash` and `created_at_ms`;
`token_hash` is an **Argon2id PHC string**, never the plaintext token
[[cite:crates/limedl-types/src/types/settings.rs:L589-L604]]. The plaintext is
generated in the settings editor at Generate/Regenerate time, carried only for
the one-time reveal, and only the hash reaches settings.json
[[cite:crates/limedl-native/src/bridge/forms/aria2_clients.rs:L30-L45]]. The
editor's `parse_aria2_clients` validates non-empty case-insensitively-unique
names and a non-empty hash without running Argon2 — Save never re-hashes
[[cite:crates/limedl-native/src/bridge/forms/aria2_clients.rs:L57-L92]]
[[cite:crates/limedl-native/src/bridge/forms/aria2_clients.rs:L1-L7]].

## Save fan-out

`Dispatcher::save_settings_with(mutate)` is the write path used by both
frontends [[cite:crates/limedl-core/src/dispatcher.rs:L294-L348]]:

1. `SettingsService::update_with(mutate)` normalizes, persists and updates memory
   [[cite:crates/limedl-core/src/dispatcher.rs:L301-L308]].
2. `registry.update_all_settings(&saved)` broadcasts to every backend — the
   broadcast keeps going when one backend errors but returns the first failure
   [[cite:crates/limedl-core/src/backend_registry/mod.rs:L95-L113]].
   `DownloadManager::apply_settings` sets the rate limiter and buffer-pool
   limits, pushes disk-type overrides into the scheduler, rebuilds the reqwest
   client **only when the proxy or user-agent changed**, re-applies logging and
   rebalances the scheduler [[cite:crates/limedl-core/src/manager.rs:L350-L393]].
   The BT backend (`RqbitBtBackend` behind `LazyBtBackend`) stores the new
   settings and, when the engine is already running, rebuilds its auxiliary HTTP
   client and applies the global download/upload rate limits to the librqbit
   session [[cite:crates/limedl-bt/src/session.rs:L190-L207]]; the lazy wrapper
   forwards the update and uses the stored snapshot as launch configuration when
   the engine has not started yet [[cite:crates/limedl-bt/src/lazy.rs:L454-L469]].
3. The CDN service is cleared when `cdn_acceleration.enabled` is false
   [[cite:crates/limedl-core/src/dispatcher.rs:L313-L318]].
4. `ConcurrencyManager` max HTTP is recomputed from the active scheduler mode and
   max BT from `bt.max_downloads` (clamped 1..=1000), then the scheduler is
   notified via `rebalance_notify` [[cite:crates/limedl-core/src/dispatcher.rs:L320-L333]].
5. Buffer-pool limits are pushed directly into `DiskIoService` as a fallback for
   broadcasts skipped in minimal (test) registries
   [[cite:crates/limedl-core/src/dispatcher.rs:L334-L345]].

`save_settings` is a wrapper that replaces the whole struct; `factory_reset`
saves defaults [[cite:crates/limedl-core/src/dispatcher.rs:L283-L292]]
[[cite:crates/limedl-core/src/dispatcher.rs:L350-L354]]. The daemon uses this path
once at startup to persist a `--download-dir` override
[[cite:crates/limedl-server/src/lib.rs:L66-L76]].

The desktop adds UI-specific side effects in `settings_sync` (autostart sync,
Aria2 RPC restart, language/tray/appearance push) — see
[[wiki:desktop/native-ui-architecture]].

## The no-shadow-copy rule

The settings read is a convenience, never a cache. `AppContext::settings()` in
the desktop reads through `Dispatcher::get_settings_blocking()`, falls back to
defaults with a warning if that fails, and its doc comment is the contract: the
core `SettingsService` behind the dispatcher is the single source of truth and
writers must use `save_settings_with`
[[cite:crates/limedl-native/src/context.rs:L38-L51]].
