# 磁盘自适应缓冲池机制

在千兆（1 Gbps）乃至万兆（10 Gbps）的高速宽带环境下，下载工具每秒接收的网络数据包可达数十万个。未经优化的传统下载器往往将数据块直接调用系统写操作，导致操作系统磁盘活动率飙升至 100%，引发前台程序无响应、系统严重卡死甚至加速闪存寿命衰减。

limedl 引入了**介质感知自适应缓冲池（Buffer Pool）**，根据存储介质的物理特性提供差异化的 I/O 调度保护。

---

## 物理介质特性的根本矛盾

```
┌─────────────────────────────────────────────────────────────┐
│ 固态硬盘 (SSD / NVMe)                                       │
│ • 无机械寻道延迟，随机读写极其迅速                           │
│ • 物理核心限制：闪存擦除块 (Erase Block) 尺寸较大 (4MB~16MB) │
│ • 痛点：频繁微小随机写入会引发严重的写入放大 (WAF)，加速寿命损耗│
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 机械硬盘 (HDD)                                              │
│ • 顺序读写吞吐可达 150~250 MB/s                              │
│ • 物理核心限制：机械磁头寻道耗时巨大 (每次寻道需 5~15 毫秒)   │
│ • 痛点：并发下载多线程争抢磁头导致磁头剧烈抖动与 I/O 队列雪崩  │
└─────────────────────────────────────────────────────────────┘
```

## 存储介质智能识别 (Disk Type Detection)

在启动下载与创建目标文件之前，limedl 会主动对目标存储驱动器进行物理特性探测：

- **Windows 平台**：
  引擎通过调用底层 Win32 API 句柄（`CreateFileW` 打开驱动器盘符），并发送设备控制码 `IOCTL_STORAGE_QUERY_PROPERTY` 查询存储属性 `STORAGE_DEVICE_SEEK_PENALTY_PROPERTY`：
  - 若系统返回设备存在寻道惩罚（Seek Penalty），判定为机械硬盘（HDD）；
  - 若不存在寻道惩罚，判定为固态硬盘（SSD）。
- **网络位置（`DiskType::Network`）**：
  UNC 共享、映射网络盘（`DRIVE_REMOTE`）、以及 Linux/macOS 上的网络或宿主转发文件系统（如 NFS/CIFS/9p/virtiofs）没有任何本地块设备可供探测——以前它们会被静默当成 SSD。现在它们被单独标记为**网络位置（介质未知）**，按 SSD 方式调度（瓶颈在传输而非寻道，远端本来就会重排写入），并在 **设置 → IO 实验室** 的磁盘类型列表中列出——这正是最需要手动覆盖的那类位置。
- **WSL 发行版（`\\wsl$\<distro>` / `\\wsl.localhost\<distro>`）**：
  它不是网络存储。该 UNC 传输背后的 9p/virtiofs 服务的是**本地**虚拟磁盘 `ext4.vhdx`，因此 limedl 会从 `HKCU\Software\Microsoft\Windows\CurrentVersion\Lxss` 中按发行版名找到 `BasePath`，对 `<BasePath>\ext4.vhdx`（`wsl --import --vhd` 布局或 WSL1 发行版没有该文件时，退回 `BasePath` 本身）执行普通本地探测，从而得到**宿主卷的真实介质**。映射成盘符的 WSL 共享（`net use Z: \\wsl$\Ubuntu`）也会先解析回 UNC 目标再走同一路径；发行版解析失败时才回退为网络位置。
- **macOS / Linux 平台**：
  本地盘通过 `/sys/block/<dev>/queue/rotational`（Linux）或 IOKit `IOMedia` 的 `Rotational`（macOS）探测；网络挂载按 fstype 归类为网络位置，其余默认 SSD 模式。
- **自定义介质覆盖 (`disk_type_overrides`)**：
  在 **设置 → IO 实验室 → 目录介质覆盖** 中显式指定某目录（如 NAS 挂载的 SMB 卷、WSL 路径、虚拟磁盘）强制按 SSD 或 HDD 调度。键是目录，匹配为规范化路径的**组件边界前缀匹配**（最长键优先）：`D:\Downloads` 覆盖其下所有内容，但不会误命中 `D:\Downloads-old`；Windows 下大小写与尾部分隔符不影响匹配。每行都会显示当前自动探测到的介质。

## SSD 模式：写入合并 (Write Combining)

针对固态硬盘的写入特性，limedl 在任务内部构建了基于内存有序红黑树（`BTreeMap<u64, Bytes>`）的合并缓冲区：

1. **零散块内存暂存**：并发网络线程拉取的各个 HTTP 分块数据，首先灌入按文件偏移量（Offset）有序排序的内存树中；
2. **块边界对齐与聚合**：当暂存数据量累积到最优对齐尺寸（如 1MB ~ 4MB）或分块连续成片时，引擎将多个分散的小块整合成一个连续的大数据流；
3. **批量异步提交**：将聚合后的大块数据提交给专用的落盘工作线程一次性执行批量写入。

**收益**：
- 将随机小 I/O 请求压制到最低，显著降低固态硬盘的**写入放大系数（WAF）**；
- 避免 SSD 缓存耗尽掉速，在持续高速下载时维持平稳的千兆/万兆写入曲线。

## HDD 模式：双缓冲池 (Double Buffering) 与单线程串行化

为了拯救机械硬盘的磁头，limedl 引入了经典的生产者-消费者双缓冲架构：

```
并发网络工作线程 (Workers)
         │
         ▼ 持续写入
┌────────────────────────────────┐
│      活跃半缓冲 (Active Half)   │  ◄── 容量达到上限 或 2秒定时器触发
└────────────────┬───────────────┘
                 │
                 ▼ 瞬间原子指针交换 (Ping-Pong Swap)
┌────────────────────────────────┐
│      落盘半缓冲 (Flush Half)    │
└────────────────┬───────────────┘
                 │
                 ▼ 按物理文件偏移严格递增排序 (Strictly Ordered)
┌────────────────────────────────┐
│     专用单线程 IoWorker 刷盘    │
└────────────────┬───────────────┘
                 │
                 ▼ 顺序写入机械磁盘 (Sequential Write)
          [机械硬盘磁头平滑移动，绝无无序抖动]
```

1. **半缓冲交替机制**：内存池划分为两个互相对称的半缓冲。前台多个下载协程持续向活跃半缓冲写入数据；
2. **乒乓指针切换**：当活跃半缓冲累积达到预设计算上限（根据可用内存与并发数动态规划，最小 64 KiB），或者 2 秒定时器超时，两个半缓冲的角色瞬间互换；
3. **单线程串行化按序落盘**：落盘半缓冲被整体移交至专属的后台 `IoWorker` 线程。`IoWorker` **严格按照文件物理偏移由小到大的顺序**执行顺序写入。

**收益**：
- 机械硬盘磁头始终保持单一方向的平滑扫描移动，彻底消除多线程乱序并发写导致的剧烈磁头寻道噪音；
- 在机械硬盘上实现高达 180MB/s+ 的满速顺序写入，彻底终结磁盘占用 100% 导致的电脑假死。

## 文件预分配与原子最终化 (FileOps)

除了缓冲机制，底层文件系统操作同样直接影响系统稳定性：

### 1. 极速空间预分配
在开始接收网络数据前，limedl 会主动校验磁盘剩余空间（保留至少 10% 的安全冗余空间），并在磁盘上为目标文件预分配物理连续簇：
- **Linux 平台**：调用高效率的 `fallocate()`；
- **Windows 平台**：优先调用 `SetFileValidData` 或 `SetEndOfFile` 预占空间。

预分配保证了下载文件在磁盘上具备最优的物理连续性，从源头杜绝了文件碎片的产生。

### 2. 原子最终化 (Atomic Finalization)
- 下载过程中的所有数据全部写入带有随机后缀的临时文件（`.tmp`）；
- 当且仅当所有数据块完整接收且校验通过后，执行原子重命名（Atomic Rename）更名为最终文件名；
- 若目标目录涉及跨存储设备或跨分区挂载，引擎采用优化的 256KB 大缓冲区进行安全流式搬迁，杜绝因突然断电导致损坏半截文件被其他软件误读。
