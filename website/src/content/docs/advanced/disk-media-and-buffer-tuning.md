# 磁盘介质探测与缓冲调优

下载速度不仅取决于网络：并发写入如果落到机械硬盘的随机寻道上，会把整机拖到“假死”。limedl 会先识别目标目录的介质，再选择写入策略；识别错误时也可以手动覆盖。

---

## 介质如何识别

| 平台 | 识别方式 |
| :--- | :--- |
| **Windows** | 读取存储设备属性：寻道惩罚、总线类型（NVMe/SCM/SD/MMC 视为 SSD）、TRIM；同时检查卷与背后的物理磁盘 |
| **Linux** | 先按 `/proc/self/mountinfo` 判断网络/宿主代理文件系统，再读 `/sys/block/<dev>/queue/rotational` |
| **macOS** | `statfs` 取得 BSD 设备，再通过 IOKit 的 `IOMedia` / `Rotational` 属性判断 |

判定结果：

- **Network**：UNC 共享、映射到远程的盘符，以及 NFS、SMB/CIFS、AFP、WebDAV、GlusterFS、Ceph、Lustre、9p、virtiofs 等远程或宿主代理文件系统。
- **SSD**：NVMe、SCM、SD/MMC、TRIM 支持，或无法识别的本地文件系统。
- **HDD**：具备明显寻道惩罚的旋转介质。

:::note[未知不等于远程]
无法识别的文件系统会退回 **SSD** 策略，而不是被当成网络盘。这样做是为了避免把本地新文件系统误判为高延迟存储；如果判断不对，请使用目录覆盖。
:::

### WSL

`\\wsl$\<发行版>` 与 `\\wsl.localhost\<发行版>` **不会**被当作网络盘：WSL 的 9p/virtiofs 服务背后是本地 `ext4.vhdx`。limedl 会从注册表 `HKCU\…\Lxss` 找到发行版的 `BasePath`，再识别存放该 VHDX 的宿主卷；找不到注册表项时才退回 Network。结果按发行版缓存。

### 虚拟机与网络共享

- 虚拟机磁盘可能被识别为 SSD 或未知；如果策略不符合实际，使用目录覆盖。
- SMB/NFS 下载目录会按 **SSD/Network 写合并**调度，不会套用 HDD 双缓冲，以避免网络文件系统上的随机写放大。

---

## 目录介质覆盖

入口：**设置 → IO 实验室 → 目录介质覆盖**。

- 键必须是**绝对路径**；Windows 支持 `\\server\share`。
- 路径会做规范化：去除首尾空白、Windows 下转小写、统一分隔符、去掉 `\\?\` 前缀与末尾分隔符。
- 匹配是**按路径分量的前缀匹配，最长键优先**：
  - `D:\downloads` 覆盖 `D:\downloads\a.bin`，但不覆盖 `D:\downloads-old`；
  - 嵌套规则优先于父目录规则。
- 覆盖会在下一次下载开始时生效，并触发设备队列重建；**正在写入的任务**会继续使用旧队列直到完成。

## 缓冲策略

| 介质 | 策略 | 默认参数 |
| :--- | :--- | :--- |
| **HDD** | 全局缓冲池 + 双缓冲，后台单线程顺序刷盘 | 池上限 `1024 MiB`，并行槽 `4`，双缓冲开启 |
| **SSD / Network** | 本地乒乓缓冲 + 写合并，减少小写入 | 写合并上限 `0`（自动，按分块大小），最大 `4096 MiB` |
| **游戏模式** | 降低磁盘 I/O 干扰 | 缓冲 `128 MiB`，并行槽 `1` |

- **游戏模式 / 超频模式**是运行时开关，不写入 `settings.json`。
- 游戏模式只影响 HDD 缓冲池；SSD/Network 仍使用各自的本地上限。
- HDD 后台按阈值做自适应同步，SSD 路径不做强制同步，以减少闪存写入放大。

## 调优建议

### 机械硬盘

- 保持 **双缓冲开启**；并发下载很多时，优先增加池上限/并行槽，而不是无限增加同时任务数。
- 如果系统内存紧张，降低池上限；过大的缓冲会把压力转移给内存与交换分区。
- 多个 HDD 任务同时写入同一块盘时，顺序写优势会被多流竞争抵消；必要时用调度器限制并行任务。

### SSD

- 写合并上限保持 `0`（自动）通常最好；手动设得过大只会增加内存占用。
- 游戏/直播时开启游戏模式，降低后台刷盘对帧时间的干扰。
- 关注剩余空间与 TRIM；长期满盘会显著降低写入性能。

### 网络盘 / WSL / 虚拟机

- 网络共享按 SSD 策略运行；不要期望 HDD 双缓冲带来顺序写收益。
- WSL 下载目录如果识别成 Network，检查注册表映射是否存在，或直接添加目录覆盖。
- 虚拟机磁盘如果被误判，优先用覆盖固定为 SSD/HDD。

## 验证与基准

- 在[性能基准](/advanced/benchmarks/)中使用 `BENCH_DISK` 指向真实目标盘，比较 HDD 双缓冲、SSD 本地缓冲与直接写入。
- 不要把基准目录放在 tmpfs/RAM 盘，否则寻道与写放大的差异会消失。
- 修改覆盖或缓冲参数后，用同一文件、同一时段重复测量，取中位数。
