# Native Desktop UI (Slint)

`crates/limedl-native` is the only shipped desktop client and the only UI over
`limedl-core`. It is a single Slint process: `build_ui` receives the engine's
`Dispatcher` and `EventBus` as plain `Arc` handles, so there is no IPC, webview
or serialization boundary between UI and engine.
[[cite:crates/limedl-native/src/ui_boot.rs:L35-L53]]

## The main / ui_boot split

`main()` is a thin wrapper: it awaits `run()` and, on error, hands the error to
`crash::report_startup_failure` (message box + crash log) before exiting
non-zero. [[cite:crates/limedl-native/src/main.rs:L56-L65]]
Without that, a failure during startup made the window never appear with nothing
written anywhere — the process has no console
(`windows_subsystem = "windows"`). [[cite:crates/limedl-native/src/main.rs:L1-L1]]

`run()` owns everything that touches the operating system, and
`ui_boot::build_ui` owns the pure UI assembly:

- `run()` parses the CLI contract `limedl-native [--hidden] [<url|magnet|path|limedl://…>]`,
  resolves the data directory, claims the single-instance slot, installs the
  panic hook, initializes logging with the **defaults**, calls `bootstrap()`,
  then re-applies logging with the **configured** settings, syncs autostart,
  optionally starts the Aria2 RPC server, decides the language and resolves the
  default download directory, then calls `build_ui`.
  [[cite:crates/limedl-native/src/main.rs:L69-L167]]
  After the window exists it installs the tray, restores window geometry,
  registers platform hooks, starts the background listeners, watches
  SIGTERM/SIGINT and finally runs the event loop.
  [[cite:crates/limedl-native/src/main.rs:L186-L303]]
- Logging comes up before the engine on purpose: a bootstrap, settings or
  migration failure is exactly the class of failure that most needs a log, and
  the second `init_logging` call only re-applies level/enabled/path.
  [[cite:crates/limedl-native/src/main.rs:L106-L121]]
- `build_ui(UiBootInputs)` receives everything that needs the OS or an async
  lookup as **already-resolved inputs** (settings, language, default directory,
  base directory, RPC shutdown handle, install kind). It is deliberately **not
  async and free of timers**: it builds the real `MainWindow`, applies
  translation and appearance, arms sleep inhibition from the loaded settings
  (`POWER_GUARD.set_enabled(settings.power.prevent_sleep)`), constructs
  `AppContext` and calls `handlers::register_all`.
  [[cite:crates/limedl-native/src/ui_boot.rs:L90-L180]]
  That is exactly the seam that lets the in-process UI tests drive the same
  window and callbacks headlessly. [[cite:crates/limedl-native/src/ui_boot.rs:L1-L14]]

## Crash reporting

`crash.rs` is the only place that can leave evidence of a panic, because the
release profile builds with `panic = "abort"` (the hook still runs on the way to
`abort()`): [[cite:crates/limedl-native/src/crash.rs:L1-L11]] [[cite:Cargo.toml:L120-L120]]

- `install_panic_hook(state_dir)` registers a hook that appends timestamp,
  thread, `file:line`, payload and `Backtrace::force_capture()` to
  `<state_dir>/logs/crash.log`, and echoes the same text to stderr.
  [[cite:crates/limedl-native/src/crash.rs:L25-L41]]
- The log rotates to `crash.log.1` past `CRASH_LOG_MAX_BYTES` (1 MiB), and the
  hook is deliberately allocation-light: a panic hook that itself panics would
  abort without a report. [[cite:crates/limedl-native/src/crash.rs:L87-L132]]
- `report_startup_failure` writes the same kind of report and then shows a
  localized `rfd` message box (the language comes from the OS locale via
  `Language::detect_system()`, since settings may not have loaded).
  [[cite:crates/limedl-native/src/crash.rs:L43-L68]]

## AppContext

`AppContext` is the shared handle bag passed to every handler. It holds the
`MainWindow` and its weak handle, the `Dispatcher`, the `EventBus`, the
`Arc<Mutex<TaskStore>>`, the toast queue, the RPC shutdown sender, scratch state
for the new-task torrent file list, the active inspector id, Labs expansion and
candidates, rewrite rules, sandbox test URL, game/overclock flags, the tray
speed limit flag and the base directory. [[cite:crates/limedl-native/src/context.rs:L17-L36]]

`AppContext::settings()` is explicitly a *read convenience*, not a cache: it
reads through the dispatcher's `get_settings_blocking()`, and writers must use
`Dispatcher::save_settings_with` so a concurrent update is not clobbered.
[[cite:crates/limedl-native/src/context.rs:L38-L51]]

## The bridge layer is pure mapping

`src/bridge/` converts between engine types and Slint models without side
effects, which is why it can be unit-tested without a window. It re-exports
domain-focused modules: `models`, `forms` (`combo`, `enums`, `to_form`,
`from_form`, `speed_limit`, `disk_override`, `aria2_clients`, `fields`),
`task_store`, `format`, `clipboard`, `labs`, `piece_map` and `setup_wizard`.
[[cite:crates/limedl-native/src/bridge/mod.rs:L1-L17]]

List-style editors follow one contract: their **editing state lives in the UI
model** and Rust parses it only at Save (`read_schedule_rows`,
`read_disk_override_rows`, `read_aria2_client_rows`).
[[cite:crates/limedl-native/src/ui_sync.rs:L70-L108]]
[[cite:crates/limedl-native/src/ui_sync.rs:L112-L121]]
Inline edits go through `set_row_data` so the in-progress input does not lose
its cursor; adding or removing rows rebuilds the model.
[[cite:crates/limedl-native/src/handlers/settings/disk_overrides.rs:L83-L124]]
The Aria2 client editor additionally generates and hashes tokens on
Add/Regenerate and only ever persists `token_hash` (an Argon2 PHC string) —
Save never re-hashes. [[cite:crates/limedl-native/src/bridge/forms/aria2_clients.rs:L34-L51]]

## Handler registration and shared plumbing

`handlers::register_all` calls one `register(ctx)` per subsystem: `task`,
`new_task`, `inspector`, `settings`, `setup_wizard`, `labs`, `updater`,
`window`. [[cite:crates/limedl-native/src/handlers/mod.rs:L1-L22]]
Each module's `register` only wires callbacks; flows shared across callbacks
live in named functions in `handlers/common.rs`, whose doc comment states the
purpose: keep the `as_weak()`/`upgrade()` boilerplate out of the subsystem
modules. `common.rs` owns `with_ui` (upgrade a weak window), `read_ui` (read a
value before spawning), `mutate_store` (mutate + refresh under the store lock),
`refresh_from_anywhere`, `reload_tasks` (re-read from the dispatcher),
`take_selection`, `refresh_after_removal`, `drop_locally`, the `TaskAction`
enum and the `spawn_action`/`spawn_batch_action`/`spawn_for_state` helpers.
[[cite:crates/limedl-native/src/handlers/common.rs:L1-L232]]

## The DownloadEvent subscriber

`event_stream::start_event_bus_listener` spawns one task that matches every
`DownloadEvent` variant explicitly (no catch-all): `Updated`, `Progress`,
`CdnProgress`, `CdnComplete`, `Warning` and `Aria2Notification`. The Aria2
variant is intentionally ignored by the desktop, because the RPC server pushes
those straight to its own clients. [[cite:crates/limedl-native/src/event_stream/bus.rs:L306-L346]]

Behavior worth knowing:

- **Removal detection**: `Updated` means "the row changed", including removal.
  `on_updated` asks `dispatcher.status(task_id)`; if the backend no longer
  knows the task, the row is dropped and the inspector closes.
  [[cite:crates/limedl-native/src/event_stream/bus.rs:L114-L141]]
- **Lagged recovery**: on `RecvError::Lagged`, the task calls `Dispatcher::list()`
  and replaces the whole store. Partial replay is impossible, so a snapshot is
  the only correct recovery. `Closed` ends the loop.
  [[cite:crates/limedl-native/src/event_stream/bus.rs:L329-L344]]
- **Notifications**: terminal `Completed`/`Failed` states produce an OS
  notification (when `notifications.enabled`) plus a toast.
  [[cite:crates/limedl-native/src/event_stream/bus.rs:L75-L112]]
- **Warning dedup**: core emits one warning per peer/mirror/disk check, so
  `WarningDedup` collapses the *same* `id:message` within a 5 s window.
  [[cite:crates/limedl-native/src/toast.rs:L147-L177]]
- **In-place model reconcile**: `refresh_ui` filters the store and hands the
  result to `apply_tasks`, which mutates the existing `VecModel<TaskItem>`
  instead of replacing it: a fast path `set_row_data`s changed rows when the
  ids are identical and in the same order, and a general path removes vanished
  rows then aligns the rest. Replacing the model would make Slint destroy and
  recreate every row, resetting hover state and losing the `TouchArea`
  double-click timestamps and an active pointer grab (which would abruptly
  dismiss an open context menu when a progress event arrives).
  [[cite:crates/limedl-native/src/ui_sync.rs:L159-L237]]

Toasts themselves are a shared `Vec<ToastEntry>` behind a mutex. `push_toast`
appends an entry with `leaving: false`, syncs the Slint model and spawns an
auto-dismiss task for the given duration; both that task and the close-button
`dismiss_toast` route through `retire_toast`, which sets `leaving` and syncs
again, then drops the entry only after `TOAST_EXIT_MS` (240 ms). The extra
state is what lets the card play its exit animation: the row stays in the model
—and in the stack layout — until the animation has had time to run, so retiring
one toast does not reflow the others mid-slide. [[cite:crates/limedl-native/src/toast.rs:L12-L145]]

`sync_toasts` reconciles the live model in place (`apply_toasts`) instead of
replacing it: a fresh `VecModel` would make the repeater destroy and recreate
every row, replaying the enter animation of untouched toasts whenever a sibling
was dismissed. Rows whose id survives are updated via `set_row_data`; only new
ids are inserted. [[cite:crates/limedl-native/src/toast.rs:L34-L88]]
The Slint card (`toast_stack.slint`) starts off-screen and flips an `entered`
flag from a one-shot `Timer`, so the property animation has an initial value to
animate from, then slides back out when `toast.leaving` flips. Rust's
`TOAST_EXIT_MS` is deliberately a little longer than the `.slint` 200 ms
animation so a slow first frame is not cut off.
[[cite:crates/limedl-native/ui/components/toast_stack.slint:L31-L62]]

## Download progress rendering

`summary_to_task_item` derives `TaskItem::is_indeterminate`: a `Queued` task
with zero downloaded bytes, or a `Downloading` task with zero downloaded bytes
and an unknown or zero total, is indeterminate; every other state — including a
`Downloading` task whose total is known — is determinate.
[[cite:crates/limedl-native/src/bridge/models.rs:L200-L207]]

The two row components render the flag differently:

- **Determinate** bars (`task_card.slint`, `task_table.slint`) animate their
  width over 250 ms, and both add a soft white highlight at the leading edge
  while the task is actively downloading between 2% and 99%.
  [[cite:crates/limedl-native/ui/components/task_card.slint:L250-L279]]
  [[cite:crates/limedl-native/ui/components/task_table.slint:L505-L548]]
  The update-download bar in `tab_about.slint` and the CDN-speedtest bar in
  `labs_dialog.slint` reuse the same width animation.
  [[cite:crates/limedl-native/ui/components/settings/tab_about.slint:L174-L183]]
  [[cite:crates/limedl-native/ui/components/labs_dialog.slint:L269-L282]]
- **Indeterminate** bars replace the fill with a highlight beam (35% of the
  track, floored at 60 px in the card and 40 px in the table) that sweeps on a
  1500 ms cycle (`mod(animation-tick(), 1500ms) / 1500ms`) and paints it with a
  `@linear-gradient` between the accent and white, so a task that has not
  reported any bytes still shows that it is alive.
  [[cite:crates/limedl-native/ui/components/task_card.slint:L281-L298]]
  [[cite:crates/limedl-native/ui/components/task_table.slint:L550-L566]]

## Settings save side effects live in one module

`settings_sync::SettingsSync` is shared by the settings dialog and the setup
wizard — the module exists because both had already grown three separate copies
of the Aria2 hot-reload block. It provides `commit` (tray limit flag),
`sync_autostart` (only when the flag changed), `sync_aria2_rpc` (stop the old
server, restart when enabled) and `push_ui`. [[cite:crates/limedl-native/src/settings_sync.rs:L1-L8]]
[[cite:crates/limedl-native/src/settings_sync.rs:L82-L139]]

`push_ui` marshals to the UI thread and applies language, tray menu,
appearance, default directory, task list, optional inspector refresh and dialog
closing. [[cite:crates/limedl-native/src/settings_sync.rs:L141-L188]]
`push_ui` also re-applies `power.prevent_sleep` to `POWER_GUARD` — deliberately
inside the `invoke_from_event_loop` closure rather than on the calling thread,
because the Windows keep-awake flag is thread-local and must be held by the same
thread that reports the download count. [[cite:crates/limedl-native/src/settings_sync.rs:L149-L160]]
It then resets `reset_confirm` on close — the About tab's two-stage
factory-reset gate is disarmed on every close path so Escape or Cancel cannot
leave the app one click from wiping the data directory.
[[cite:crates/limedl-native/src/settings_sync.rs:L177-L182]]

## Platform integration

### Single instance

`InstanceClaim::claim(base_dir)` resolves to one of two strategies, and the
primary handle must stay alive for the whole process — dropping it releases the
claim. The handle is held, not read: `ClaimState::Primary` carries a
`PrimaryHandle` that on Windows wraps a raw mutex `HANDLE`, and the field is
deliberately exempted from `dead_code` because keeping the value alive (never
calling `CloseHandle`) is the entire point. [[cite:crates/limedl-native/src/single_instance.rs:L56-L86]]

- **Windows**: a session-local named mutex (`Local\limedl-native-single-instance`).
  Ownership is read from `GetLastError() == ERROR_ALREADY_EXISTS` after
  `CreateMutexW`; secondary launches focus the existing window with
  `FindWindowW` + `ShowWindow(SW_RESTORE)` and forward the payload via
  `WM_COPYDATA`. [[cite:crates/limedl-native/src/single_instance.rs:L168-L239]]
- **macOS / Linux**: an exclusive advisory lock on `<data-dir>/instance.lock`
  (`File::try_lock`, released by the kernel on process death, so a crash cannot
  leave a stale owner) plus a Unix domain socket that the primary publishes and
  secondary launches connect to.
  [[cite:crates/limedl-native/src/single_instance.rs:L257-L313]]
  The socket path falls back to a short hashed name under the temp directory
  when the data directory is deeper than the `sun_path` budget (100 bytes).
  [[cite:crates/limedl-native/src/single_instance.rs:L31-L35]]
  [[cite:crates/limedl-native/src/single_instance.rs:L315-L328]]

`notify_primary` **returns whether the request reached a primary**, and on Unix
a short retry window (2 s, 50 ms interval) absorbs the "double-clicked while the
first launch is still starting" race. [[cite:crates/limedl-native/src/single_instance.rs:L37-L43]]
[[cite:crates/limedl-native/src/single_instance.rs:L350-L396]]
A `false` return makes `run()` report the failure through the startup-error path
instead of exiting quietly. [[cite:crates/limedl-native/src/main.rs:L88-L100]]
This replaced a fixed loopback TCP port: any unrelated program that happened to
own that port looked like a running limedl, the launch was classified
secondary, the notification connect failed silently, and the user got neither a
window nor an error. [[cite:crates/limedl-native/src/single_instance.rs:L16-L22]]

### Autostart

`autostart.rs` is a thin dispatcher over per-OS modules: only the `#[cfg]`
selected backend (`windows_impl`, `linux_impl`, `macos_impl`, or a no-op
fallback that reports "already registered") is compiled, and the shared helpers
(`current_exe_string`, `registration_is_current`) are used by all of them.
[[cite:crates/limedl-native/src/autostart.rs:L276-L334]]
Every OS registration appends `--hidden`, so login starts go to the tray.
[[cite:crates/limedl-native/src/autostart.rs:L1-L12]]
Windows portable/NSIS uses the HKCU `Run` key; MSIX uses the
`windows.startupTask` manifest extension because registry `Run` is virtualized
in MSIX; Linux writes an XDG `.desktop`; macOS writes a LaunchAgent.
[[cite:crates/limedl-native/src/autostart.rs:L1-L6]]
The `expected_command` helper — which quotes a spaced executable path and
appends `--hidden` — is shared by Windows and Linux only
(`#[cfg(any(windows, target_os = "linux"))]`); macOS builds its plist
`ProgramArguments` array from `current_exe_string` directly.
[[cite:crates/limedl-native/src/autostart.rs:L20-L33]] [[cite:crates/limedl-native/src/autostart.rs:L243-L257]]
On Unix, `registered_for_current_exe` and `sync_from_settings` re-register when
the executable moved (portable extraction to a new folder, debug vs release) or
lost the hidden flag. [[cite:crates/limedl-native/src/autostart.rs:L35-L45]]
[[cite:crates/limedl-native/src/autostart.rs:L366-L385]]

### Tray

The tray menu (show, pause all, resume all, speed-limit check, game mode, open
download dir, quit) is built with `muda`, and
`update_tray_menu_and_tooltip` rebuilds it on the UI thread.
[[cite:crates/limedl-native/src/tray.rs:L10-L75]]
On Linux the tray is a StatusNotifierItem served over the session D-Bus.
**Building the icon is best-effort**: a missing StatusNotifier host (GNOME
without the AppIndicator extension, a bare window manager) makes `build()`
fail, and `run()` logs `tray_init_failure_message` and keeps going instead of
aborting the launch before the window is shown — the window is the primary UI,
the tray is an extra. [[cite:crates/limedl-native/src/main.rs:L195-L212]]
[[cite:crates/limedl-native/src/tray.rs:L43-L61]]
The quit item releases the power lock before asking the event loop to stop.
[[cite:crates/limedl-native/src/event_stream/tray.rs:L137-L146]]

### Sleep inhibition

`power.rs` owns the one process-wide `PowerGuard` (`POWER_GUARD`, a `LazyLock`
in `main.rs`), and it is a two-input state machine rather than a boolean: the
desired state is `enabled && running downloads > 0`, where `enabled` is
`AppSettings::power.prevent_sleep` and the count is the same number the UI
counters show. [[cite:crates/limedl-native/src/power.rs:L1-L28]]
[[cite:crates/limedl-native/src/main.rs:L34-L35]]

- `update(active_downloads)` is called from `refresh_ui` and from the store
  mutation path in `event_stream/bus.rs`, so the lock follows the visible task
  state. [[cite:crates/limedl-native/src/ui_sync.rs:L135-L137]]
  [[cite:crates/limedl-native/src/event_stream/bus.rs:L52-L57]]
- `set_enabled(bool)` applies the setting; `release()` drops the lock
  unconditionally (quit, factory reset) and may be followed by a re-acquire if
  downloads are still running. [[cite:crates/limedl-native/src/power.rs:L99-L133]]
- `GuardState::desired` is what keeps this cheap: only a *change* of desire
  touches the OS API. Recomputing per UI refresh would re-issue the platform
  call several times a second, and a rejected logind call would retry — and log
  a warning — on every frame. A failed acquire therefore stays latched off
  until the next rising edge, and the lock liveness is decided under one mutex,
  so racing callers cannot take two locks or release one another's.
  [[cite:crates/limedl-native/src/power.rs:L36-L58]] [[cite:crates/limedl-native/src/power.rs:L135-L158]]

The held lock is one RAII guard per platform, acquired on construction and
released on `Drop`. Every path is best effort — a failure is logged once and the
download continues:

- **Windows**: `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED |
  ES_AWAYMODE_REQUIRED)`, which keeps the system (and so the network stack)
  running while the display may go dark. The flag is per **thread**, so the
  guard records the thread that took it and logs an error if it is ever dropped
  by another; the toggle is applied on the UI thread for that reason.
  [[cite:crates/limedl-native/src/power.rs:L184-L233]]
- **macOS**: an IOKit `PreventUserIdleSystemSleep` assertion
  (`IOPMAssertionCreateWithName`/`IOPMAssertionRelease`), named
  `limedl: active downloads` so `pmset -g assertions` shows the holder. The
  idle-*system* assertion rather than `PreventUserIdleDisplaySleep` is what
  keeps the transfer alive without pinning the screen.
  [[cite:crates/limedl-native/src/power.rs:L243-L302]]
- **Linux**: `org.freedesktop.login1.Manager.Inhibit("idle:sleep", "limedl",
  "Downloading", "block")` on the system bus. logind releases the inhibit when
  the returned pipe fd is closed, so the fd *is* the lock and the guard only has
  to hold it; the D-Bus connection that created it is dropped immediately. No
  systemd-logind, or a polkit denial because the session is not active (WSL, a
  headless SSH login), makes the call fail — logged once per download session,
  and the download proceeds. [[cite:crates/limedl-native/src/power.rs:L304-L361]]
  [[cite:docs/desktop-build-and-packaging.md:L95-L101]]
- **Other targets** keep the no-op guard, so the setting and the state machine
  behave identically while the machine's own power policy is left alone.
  [[cite:crates/limedl-native/src/power.rs:L374-L393]]

The setting itself (`power.preventSleep`, default on) is armed at boot by
`build_ui` and re-applied by `SettingsSync::push_ui` after a save; the switch is
`prevent_sleep_toggle` in `tab_appearance.slint`, in the row block right below
autostart. [[cite:crates/limedl-native/src/ui_boot.rs:L145-L147]]
[[cite:crates/limedl-native/src/power.rs:L44-L47]]
[[cite:crates/limedl-native/ui/components/settings/tab_appearance.slint:L170-L183]]
What none of this does: override the lid, `shutdown -h`, or a privileged
suspend request — and none of it keeps the display on.
[[cite:crates/limedl-native/src/power.rs:L21-L23]] [[cite:docs/desktop-build-and-packaging.md:L91-L94]]

### Window geometry

Geometry is saved on exit (Windows additionally on `WM_EXITSIZEMOVE`/`WM_SIZE`
via the window subclass).
[[cite:crates/limedl-native/src/platform_win.rs:L347-L367]] [[cite:crates/limedl-native/src/main.rs:L305-L306]]
Restoration differs by platform:

- **Windows** reads `GetWindowPlacement` so a maximized window still saves its
  restorable size, and uses `MonitorFromRect` to reject rectangles that are no
  longer on any monitor (centering instead). A maximized show command is never
  issued on a hidden window. [[cite:crates/limedl-native/src/platform_win.rs:L589-L604]]
  [[cite:crates/limedl-native/src/platform_win.rs:L634-L712]] [[cite:crates/limedl-native/src/platform_win.rs:L794-L804]]
- **macOS/Linux** use Slint's `Window::position/size/is_maximized` and a
  `MAX_PLAUSIBLE_COORD` (±20000 px) heuristic instead of real monitor geometry.
  [[cite:crates/limedl-native/src/platform_win.rs:L102-L116]]
  [[cite:crates/limedl-native/src/platform_win.rs:L606-L615]]
  [[cite:crates/limedl-native/src/platform_win.rs:L714-L721]]

Because the OS window only exists after the event loop starts,
`ensure_restored_window_placement` reports whether placement was applied, and
`schedule_window_placement_restore` retries every 250 ms until it does.
[[cite:crates/limedl-native/src/platform_win.rs:L617-L628]]
[[cite:crates/limedl-native/src/platform_win.rs:L750-L771]]
[[cite:crates/limedl-native/src/ui_sync.rs:L360-L390]]
On a `--hidden` tray start the restore is not scheduled at boot; placement is
applied by `restore_and_show_window` the first time the window is shown.
[[cite:crates/limedl-native/src/main.rs:L298-L301]]
[[cite:crates/limedl-native/src/ui_sync.rs:L338-L358]]

## Theming

`ui/theme.slint` is generated by `cargo xtask theme generate` from the mapping
tables in `xtask/src/theme.rs` (see [[wiki:operations/build-release-and-ci]])
and exposes a `Theme` global plus two enums: `ColorModePref { System, Light,
Dark }` and `ThemeAccent { Lime, Amber, Sky, Violet, Monochrome }`. `mode` comes
from `appearance.color_mode`, `accent` from `appearance.theme_color`, and the
`dark` flag resolves the explicit choice or the OS scheme
(`Palette.color-scheme`) in system mode.
[[cite:crates/limedl-native/ui/theme.slint:L1-L31]]
Components must use `Theme.c<hex>` tokens instead of hardcoded hex (checked by
`cargo warden slint-theme` against the allowlist in `warden.toml`); the
brand-accent tokens (`c84cc16`, `ca3e635`, …) select their value from `accent`,
while status colors (success/warning/danger/info) stay fixed.
[[cite:crates/limedl-native/ui/theme.slint:L9-L13]]
[[cite:crates/limedl-native/ui/theme.slint:L245-L247]]
[[cite:warden.toml:L15-L40]]
`apply_appearance` maps the `ColorMode`/`ThemeColor` settings onto the two enum
properties, then syncs the OS window theme from the resulting `dark` flag.
[[cite:crates/limedl-native/src/ui_sync.rs:L392-L409]]
[[cite:xtask/src/theme.rs:L218-L307]]
