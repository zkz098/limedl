# Adding or changing a translated string

Both halves of the desktop UI read the **same** gettext catalogs —
`crates/limedl-native/lang/<locale>/LC_MESSAGES/limedl-native.po` for `zh_CN`,
`zh_TW` and `en`. There is no second string table to keep in sync:

| Where the string is written | How it resolves |
| --- | --- |
| `.slint` files | `@tr("…")`; slint-build bundles the catalogs |
| Rust (`i18n/*.rs`, handlers, validation) | `i18n::tr("…", lang)` / `i18n::tr_fmt("…", lang, &[…])` |

`msgid` is the **English source string**, and it doubles as the fallback: a key
that is missing from a catalog renders English instead of failing.

## The generated table

`crates/limedl-native/src/i18n/catalog.rs` is generated from the `.po` files:

```cmd
cargo xtask i18n generate
cargo xtask i18n check
```

`check` — and the `i18n_catalog_matches_repo_catalogs` test, which runs in the
normal `xtask` test job — fails when the file is stale. **Never edit
`catalog.rs` by hand**: edit the `.po` files and regenerate. The column order is
`Language::catalog_index` (`zh_CN`, `zh_TW`, `en`) and must match `LOCALES` in
`xtask/src/i18n.rs`; `i18n::tr::tests::catalog_columns_follow_language_order`
pins that contract.

## Adding a message

1. Add the English source as `msgid` and its translations as `msgstr` to all
   three `.po` files. Placeholders are positional `{}`: they go through
   `i18n::tr_fmt` on the Rust side and `@tr("… {}", arg)` on the Slint side, so
   one message can serve both.
2. From Rust, call `i18n::tr("the English source", lang)` (or `tr_fmt`). The key
   must be a literal (or a `const`): the
   `every_rust_message_exists_in_the_catalogs` test scans the Rust sources for
   `tr("…")` / `tr_fmt("…")` literals and fails on a key that is not in the
   catalog.
3. Run `cargo xtask i18n generate`.

## What the tests enforce

| Test | Fails when |
| --- | --- |
| `i18n::tests::test_all_slint_tr_strings_in_po_catalogs` | a `@tr` string is missing from a catalog |
| `i18n::tests::every_rust_message_exists_in_the_catalogs` | a `tr`/`tr_fmt` key is missing from a catalog |
| `i18n::tests::catalog_columns_are_complete_and_english_is_cjk_free` | a translation is empty, or Chinese reaches the English column (the two language self-names are the allowlisted exception) |
| `xtask::tests::i18n_catalog_matches_repo_catalogs` | `catalog.rs` is stale |

Rust-side text must still go through the `i18n` module — never inline a
user-visible string, and never hardcode CJK (English builds must not leak
Chinese).

## The `msgctxt` exceptions

Four messages are deliberately **not** in the catalog, because the same English
source needs two different translations depending on where it is shown and the
generator has no `msgctxt` support yet:

| msgid | `.slint` (`@tr`) translation | Rust translation |
| --- | --- | --- |
| `Downloading` | `正在下载` (long status label) | `下载中` (list cell) |
| `SSD` | `SSD` (short badge in the media ComboBox) | `SSD 固态硬盘` (IO baseline summary) |
| `HDD` | `HDD` | `HDD 机械硬盘` |
| `Unlimited` | `不限` (speed-limit ComboBox option) | `不限速` (schedule summary) |

They stay as documented local three-language tables in
`i18n/task.rs` (`format_state_label`, `format_disk_type_name`) and
`i18n/schedule.rs` (`format_schedule_summary`). Migrating them means teaching
`xtask/src/i18n.rs` to parse `msgctxt` and keying the catalog by
`(context, msgid)` — worth doing only if more conflicts appear, since the
alternative (one of the two call sites losing its wording) is a user-visible
regression, and Slint's own lookup would have to be checked against the
duplicate-msgid entries first.

Everything else in `i18n/*.rs` resolves through the catalog. A new
three-language `match lang` in a Rust-side string function is a regression: use
`tr`/`tr_fmt`, or add a row to this table with the reason.

## Migrating a remaining `match lang` table

`i18n/toast.rs` and `i18n/validation.rs` are migrated and are the reference
shape: a `format_*` function is one `tr`/`tr_fmt` call. The remaining
three-language matches in `i18n/*.rs` (`task.rs`, `dialogs.rs`, `tray.rs`,
`cdn.rs`, `schedule.rs`, `disk.rs`, `rewrite.rs`) migrate the same way — move the
three arms into the `.po` files as `msgid`/`msgstr`, then replace the `match` with
a single lookup. `i18n/validation.rs` also shows how a label table moves to a
`msgid()` arm plus `label() = tr(self.msgid(), lang)`.
